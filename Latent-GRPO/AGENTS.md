# Latent-GRPO 协作规则

> 本项目使用 Project Cairn 组织项目知识：`AGENTS.md` 是规则与导航入口，`cairn/` 是项目知识与状态层。
> 同目录的 `CLAUDE.md` 应只包含一行 `@AGENTS.md`，使 Claude Code 读取同一套规则；Codex 直接读取本文件。

## 项目一句话简介

用于优化词表空间隐式推理的 GRPO 强化学习框架。

> 本文件由 `cairn init` 生成，已填入本项目的定位和 provider 配置；其他项目复用前应各自运行初始化。

## 初始化配置

- 毕业 provider：尚未配置（暂缓对接——首次毕业时连接知识库）
- 知识库索引：尚未配置
- 毕业目标：尚未配置

## 进入项目后的阅读顺序

1. 首先阅读本文件（AGENTS.md）。
2. 如果存在 `cairn/ROADMAP.md`，阅读其中的路线图、当前重点和开放问题（ROADMAP 是可选文件，最小初始化的项目可能没有该文件）。
3. 阅读 `cairn/LOG.md` 最近的条目（最新条目在最上方），了解近期进展和关键决策。
4. 根据当前任务按需阅读相关的 `cairn/` 知识专题文档。

## 文档职责

| 文件 | 作用 | 维护方式 |
|---|---|---|
| 根目录 `AGENTS.md` | 规则与导航 | 很少变更，不超过 60 行 |
| 根目录 `CLAUDE.md` | 单行 `@AGENTS.md` 桩文件 | 创建一次，之后不再改动 |
| `cairn/ROADMAP.md` | 路线图与进度 | 原地更新，保持精简 |
| `cairn/LOG.md` | 按时间记录的日志 | 新条目添加到顶部（最新优先），每条不超过 20 行，只写摘要与指针 |
| `cairn/<topic>.md` | 知识专题文档（当前真相） | 原地更新；陷阱写入正文并通过 `contains` 标记；修订时在 LOG 中添加指针 |
| `cairn/Reference/` | 外部原始输入 | 按需创建，只追加不修改 |
| `cairn/Cited.md` | 知识库引用列表 | 只记录指针，绝不复制来源正文 |

> 其他内容只在出现具体信号时创建（需要记录决策、已解决陷阱、目标持续超过一个会话），不要预先建立空壳。由代码或流程使用的工程资产（契约、配置、规范）不由本系统管理；它们保留在代码树中，不放入 `cairn/`。

## 冲突仲裁规则

- 优先级：**知识专题文档 > LOG 历史**；规则层面的冲突由本文件裁决。
- 业务与设计结论以 `cairn/` 知识专题文档中的最新记录为准，而不是较旧的 LOG 条目。

## 知识库使用惯例

- 在开展如下工作前：其可复用内核——即它产出或依赖的任何结论——够格毕业，应先查阅本项目已有的 `cairn/` 知识专题文档；当前尚未连接外部知识库（provider 已暂缓对接——见上方“初始化配置”），因此外部索引检查和 `cairn/Cited.md` 引用将在连接后启用。

## 文档协作规则

- 修改前先判断用户要“讨论/建议”还是“直接编辑文档”；当用户说“先看看/先评估”时，先给出分析，不要直接改写正式文档。
- 更正过去的判断时，应追加更正说明，不要静默覆盖。
- 不要把未经确认的判断写成既定事实。

## 知识沉淀规则

- 每次取得实质进展后，在 `cairn/LOG.md` 顶部添加一条记录（摘要与指针）；结论沉淀到 `cairn/` 知识专题文档中。
- 跨项目可复用经验应在知识库连接后通过毕业机制沉淀（provider 已暂缓对接——见上方“初始化配置”）。
