# Agent C：target variables 到训练链路的映射审计

## 0. 范围、结论与状态口径

- 本报告只读审计了 `./spec/target_variables.md`、`./spec/02_SYSTEM_AND_IMPLEMENTATION_CONTRACT.md`、`./spec/03_METRICS_STORAGE_CONTRACT.md`、`./spec/05_VALIDATION_AND_DELIVERABLES.md`，以及作者仓库的 trainer、actor、rollout、SGLang latent sampler、reward、advantage、checkpoint/eval 链路。
- 未运行 Python、未导入包、未安装依赖、未启动训练，也未修改 `./Latent-GRPO/**`。
- 当前阶段 RTM 的 `status` 只使用 `planned`、`unavailable_with_reason`、`blocked`。代码中已经存在的量写成“direct existing”只表示**静态观察点存在**，不表示新契约已经 implemented/verified。
- 五类结论：`direct existing`（当前 DataProto/metrics 已有）；`adapter exposure`（局部已有但未返回/未绑定稳定 ID）；`new logging computation`（从现有 tensor 做局部 reduce）；`checkpoint-only probe`（只在 checkpoint 固定小批量执行）；`unavailable until runtime probe`（shape/dtype/device/shift/DP/TP/EOS 语义未实测）。

关键结论：

1. rollout 侧 `rollout_noisy_topk_token_ids`、`rollout_perturbed_topk_scores`、clean top-K 和实际 `noisy_mixture_weights` 已在 SGLang 内产生并沿返回链传入 verl；不需要为这些量补做 full forward，也绝不能持久化 full-vocabulary logits/Gumbel。
2. pre-update old-log-prob forward 已返回 `old_topk_indices`/`old_topk_probs`，可作为 Support 的唯一候选观察点；但其当前输出包含 shift/unpad/SP 路径，必须 runtime probe 证明与 rollout 的 trajectory/latent position/K 严格对齐，失败时整族 unavailable，禁止截断/广播/补 forward。
3. PPO loss、clip fraction、KL 和 entropy 有现成标量；importance-ratio mean/std 没有现成输出，但 `ratio` 已在 loss 函数内存在，可附带充分统计量，不增加 forward。
4. 作者代码只维护 `global_steps`，没有“成功参数更新才递增”的独立 `optimizer_step`。optimizer 非有限梯度会跳过更新，因此不能用 global step 替代 optimizer step。
5. `uid` 在 prompt repeat 前生成，能作 group ID 候选；作者没有 stable `trajectory_id`。必须在 repeat 后、任何 balance/filter/select 前建立 `(group_id, trajectory_id)` 并随 reorder 传播。
6. Optimal Correct Path 的选择公式存在，但 winner 仅为函数内局部 `winner_idx`，没有返回，且 old log-prob 缺失时会随机 fallback；契约路径必须要求 old log-prob、返回 winner stable ID/score，并禁止 Stage 3 从 Parquet 回读或从置零后 advantage 反推。
7. `surrogate_margin` 和 FlipGrad 公式已经在 actor 局部函数中出现；Stage 2 只可暴露/测试统计接口，不写每步 `onesided/*`。7 个 one-sided 指标只在 checkpoint probe 写。credit 默认关闭，只有 checkpoint-only 的受控 `autograd.grad` 路径，且在符号/RNG/.grad/参数/显存/时间验证前不得开启。

## 7. 下一阶段建议的接口边界（设计，不是代码）

1. `UpstreamBatchIdentityAdapter.attach_after_repeat_before_reorder(batch, step)`：产生稳定 group/trajectory IDs，并确保 DataProto reorder/select/concat 传播。
2. `AdvantageObservation`：由 Latent-GRPO advantage 函数一次返回 final advantages、group sufficient facts、winner stable ID/score；不修改算法的 candidate 语义。
3. `ActorStatsSink`：在 `compute_policy_loss` 的 ratio/clip/KL 与 `logprobs_from_logits_topk_gumbel` 的 margin/trigger 已存在处做 detached GPU reduce；Stage 2 sink 只返回统计包，不创建 `onesided/*` event。
4. `RolloutLatentFacts`：保留现有 SGLang top-K 返回；普通 step 只计算 mixture stats，Support step 仅缓存 selected trajectories 的 IDs，checkpoint eval仅转存 clean IDs/probs。
5. `SupportObserver`：消费已有 old-log-prob forward 的 `old_topk_indices`，任何 alignment probe 不通过即 family unavailable，绝不补 forward。
6. `CheckpointProbeRunner`：独立 RNG、固定 prompt/profile，复用训练 reward/advantage/mask链；one-sided默认开，credit默认关；credit开启时只调用一次最小 `autograd.grad`，结束恢复 RNG 并比较 params/optimizer/.grad/counters。
7. `MetricEvent + DistributedStatPacket + ParquetDatasetWriter`：event 创建即冻结 step context；worker只返回充分统计，driver/rank0 append-only 原子写；不让计算图 Tensor 进入队列。

## 8. 必须由目标机器 runtime probe 解决的问题

- `old_topk_indices/old_topk_probs` 的真实 shape、response slice、roll shift、dynamic-batch reverse、Ulysses SP/DP 聚合语义；静态代码 `dp_actor.py:342-351,461-473` 还显示 top-K 与 log-prob 的恢复路径并不完全一致。
- `rollout_topk_*` 的 dtype/device/K、padding 值与 latent sentinel 语义；当前 `_post_process_outputs` 对 float top-K facts 使用 `pad_token_id`（`sglang_rollout.py:219-223`），只能靠严格 mask 排除。
- clean top-K probability space：静态看是 full distribution softmax后 top-K 原概率（`sampler.py:146-149`），但 temperature、TP和返回顺序需实测；list sum不应默认等于1。
- entropy 来自 old-policy还是actor update、概率空间和 mask，尤其 `entropy_coeff=0` 时 actor update不计算 entropy而 old-log-prob forward会计算。
- reward 统计单位和 correct 判定：Naive manager把 scalar写在最后有效 token（`naive.py:42-86`），但真实 profile/reward manager可能不同。
- EOS/stop是否计入 response/generated长度，overlong/truncated判定与 SGLang finish reason。
- `advantage==0` 阈值、first-step shift与 latent policy-loss eligible mask。
- FSDP/TP 下 `component_log_prob.requires_grad`、credit一次 autograd显存和 `.grad` 污染风险、alignment符号。
- optimizer skip/overflow的可观测成功信号，以及 checkpoint中 optimizer step/RNG元数据的真实可恢复性。

这些问题在 probe 前不得填猜测值；对应 family 应按 `missing_runtime_interface`、`shape_mismatch`、`alignment_failed`、`runtime_probe_failed`、`checkpoint_missing_metadata` 等稳定 reason 表达。
