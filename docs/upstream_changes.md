# Upstream changes

## 2026-08-03 · Task 4c review fixes: semantic guards and observer fail-closed

- `dp_actor.py` now checks the FlashAttention cross-entropy capability at the beginning of every latent Gumbel micro-batch, before actor forward work. `torch_functional.logprobs_from_logits_topk_gumbel()` also raises the same explicit error if reached without that implementation; it no longer silently substitutes ordinary label log-probability. Non-Gumbel/non-latent calls retain their existing fallback behavior.
- `ray_trainer.py` validates latent or observer-enabled runs before worker startup and rejects `actor.use_dynamic_bsz=true`, `rollout.log_prob_use_dynamic_bsz=true`, and `actor.use_fused_kernels=true` with stable messages. Those paths lack proven Top-K/component alignment; non-latent observer-off upstream use remains compatible.
- `BufferedObserver` is now explicitly synthetic-only. `LATENT_GRPO_OBSERVER_ENABLED=1` without an injected driver-owned sink fails closed; a production sink must declare `durable=true`, `enabled=true`, and implement `emit`. The current runner does not yet inject the authoritative Parquet writer, so eval raw-fact persistence is `unavailable_with_reason=authoritative_eval_sink_not_integrated`, not end-to-end implemented.
- The eval interface keeps generation ordinals across all dataloader batches in one validation call and normalizes exact numeric 0/1 correctness to booleans while rejecting other numeric values. This improves the interface contract but does not upgrade persistence status.
- Mac verification is dependency-free AST/synthetic testing only. CUDA FlashAttention imports, the real writer transport, Ray/FSDP payloads, and schema-complete `eval_question_results` remain `target_machine_test_deferred` or unavailable as stated above.

## 2026-08-03 · Stable identity/OCP review fixes

- Enabled identity attachment now lazily imports NumPy and writes one-dimensional `np.ndarray` columns (`group_id` as object strings and `trajectory_id` as integer ordinals), matching `DataProto.check_consistency`, NumPy select/filter, concat, and reorder semantics. Disabled observation still imports no NumPy and mutates nothing; enabled observation fails closed with a clear error if NumPy is unavailable.
- The persistent trainer observer is now passed into `compute_advantage`. Enabled GRPO calls opt into the four-value OCP return, pass both stable ID arrays separately from the upstream random `uid`, and emit each detached winner fact. Disabled calls retain the original three-value core return and arguments.
- OCP include/exclude facts validate that every member of one upstream UID maps to exactly one stable group ID. The emitted group ID is that stable ID; winner selection and masked mean old-log-probability calculations remain unchanged.
- macOS dependency-free verification executes the identity/fact helper and AST wiring contracts. Real NumPy `DataProto` indexing and Torch numerical default/opt-in equivalence tests are present but explicitly skipped on this host because NumPy, Torch, Ray, and TensorDict are unavailable; they remain target-machine gates.

## 2026-08-02 · Stable post-repeat identity and OCP facts

- `ray_trainer.py` now calls an optional adapter immediately after rollout repeat and before union, balancing, filtering, accumulation, or reordering. If the adapter is unavailable or the observer is disabled, the original batch path is unchanged.
- `core_algos.py` OCP include/exclude functions accept optional `trajectory_ids` and `return_observer_data=False`. The default return remains `(scores, scores, id2std)`; opt-in adds winner local index, trajectory ID, and response-mask mean old log-probability without changing candidate or winner selection.
- The external adapter is standard-library-only and provides deterministic group/trajectory identities, DataProto-like attachment, a no-op observer, and detached OCP fact/event types.
- When observation is enabled, the outer launcher prepends the workspace root to `PYTHONPATH`, making the adapter importable from the upstream `verl-0.4.x` working directory. Disabled launches preserve the incoming `PYTHONPATH`.
- Verification on macOS is limited to synthetic unit tests, AST parsing, and source-order contracts; no torch, Ray, SGLang, or CUDA module is imported.

## 2026-08-02 · Optimizer outcome and component-statistics observer

- `verl/workers/actor/dp_actor.py` preserves `_optimizer_step()`'s existing `grad_norm` return and records the actual branch outcome: `did_step=true` only after `actor_optimizer.step()` returns; a non-finite gradient records a skip without incrementing the per-update success count. The plain observer payload is opt-in through `LATENT_GRPO_OBSERVER_ENABLED` and contains no optimizer state, parameter tensor, gradient tensor, logits, or component tensor.
- `verl/workers/fsdp_workers.py` advances the actor scheduler only when the actor reports `update_count > 0`. This prevents a skipped non-finite update from moving the learning-rate schedule. When observation is disabled, the existing `DataProto(meta_info={"metrics": ...})` shape is retained; enabled runs add a small `latent_grpo_observer` metadata dictionary.
- The actor-local component hook reuses the existing pre-update forward's selected logits and rollout component scores, reduces them immediately under `torch.no_grad()` to `sum`, `sum_sq`, `count`, `min`, non-finite/masked counts, negative/near-zero counts, and FlipGrad-trigger count, and exports scalars only. Definition `stage2_surrogate_v1` fixes the near-zero threshold at `1e-6`; both are copied into the observer packet. The hook adds no forward, backward, sampling operation, persistent graph, or training gradient hook. Unsupported/misaligned paths emit an explicit unavailable reason.
- A confirmed author bug in `compute_log_prob()` is fixed: `topk_logits` is now concatenated from `topk_logits_lst`; the old line concatenated `topk_ids_lst` into the logits slot.
- `latent_grpo_runner/upstream_adapter.py` includes a standard-library reference reducer used by Mac synthetic tests. Upstream actor code does not import the outer package, avoiding a new mandatory runtime dependency or working-directory assumption.
- Rollback is covered by reversing the aggregate `patches/latent_grpo_observer.patch` after it is generated. Target-machine validation remains required for real FSDP consensus on skip/success, scheduler behavior under distributed non-finite gradients, CUDA numerical agreement of sufficient statistics, and observer metadata transport through Ray collectives.

### 2026-08-03 review-fix addendum

- `update_actor` now uses a custom DP collector instead of placing rank-local facts in metadata that `DataProto.concat()` silently takes only from rank 0. The collector preserves every worker packet with an explicit `worker_rank`; the ordinary concatenated `DataProto` return remains compatible.
- The Ray coordinator removes `latent_grpo_worker_observers`, requires exact optimizer-attempt consensus across all expected ranks, and merges component sufficient statistics by addition/minimum. Missing/duplicate ranks, outcome disagreement, unavailable component paths, schema mismatch, or definition mismatch fail closed. A three-worker synthetic test proves nonzero rank 1/2 values enter global `sum`, `sum_sq`, integer counts, and `min`; no worker mean is accepted.
- Component capture now receives the exact response domain used by policy loss (`loss_mask` for multi-turn, response attention mask otherwise). Max-length advantage zeroing happens before the same forward, so both Gumbel gating and observer statistics see the final advantage. Prompt, padding, hard-token sentinel, response/loss exclusions, non-finite values, and K/shape alignment are handled explicitly; misalignment makes the component family unavailable.
- Scheduler semantics are intentional even with observer off: any successful optimizer attempt advances the existing outer-update scheduler once; an all-skipped update does not advance it. This is an algorithmic correctness fix, not a logging-only change.
- Runner profiles now declare `features.metrics_enabled=true`, and the launcher authoritatively maps this to `LATENT_GRPO_OBSERVER_ENABLED=1`; `--disable-metrics` maps to `0`, including resume. However, the current code still does **not** inject a driver-owned `AppendOnlyPartWriter`/schema/Stage1/2-builder sink into `main_ppo`. Real metrics launch is therefore blocked before target probing/model load with `unavailable_with_reason=durable_parquet_sink_not_wired`. No buffered observer or ordinary JSONL is used as a substitute.
